# Internship system

## Use two recruiting horizons

The course starts in September 2026 with no programming experience. Summer 2027 is a reach target because recruiting has begun and the first flagship will not ship until later. Apply when eligible, but do not invent skills or projects.

Summer 2028 is the full-portfolio target. By then, the learner can apply with both flagships, deeper interview preparation, and outside review.

As of September 8, 2026, some 2027 internships are already open. The Ellipsis Labs 2027 role values tested code, computer-science fundamentals, full-stack or backend experience, and ownership. BitGo lists several early-career engineering roles. Google's Summer 2027 US software role says that its rolling window may close on September 25, 2026. Check every original posting because availability and eligibility change.

Sources: [Ellipsis Labs 2027 internship](https://jobs.ashbyhq.com/ellipsislabs/02136b22-35b1-4b3d-8bef-567c3380a849), [BitGo early-career openings](https://job-boards.greenhouse.io/bitgowinter2027), [Google Summer 2027 software internship](https://www.google.com/about/careers/applications/jobs/results/100648618540573382-software-engineering-intern-bs-summer-2027)

## Complete the first 14 days

### Days 1 through 3

1. Write down your school, major, graduation date, grade-point average if useful, work history, activities, awards, and coursework.
2. Create a one-page general software resume. Do not create a tokenization version before you have tokenization work.
3. Add "US citizen" only when the application or recruiter needs work-authorization clarity.
4. Clean your GitHub profile and remove secrets or unprofessional public material.
5. Create the private application tracker described below.

### Days 4 through 7

1. Check general software, fintech, trading, and crypto internships.
2. Apply to roles whose minimum requirements you can state honestly.
3. Do not list `x/365` as a project until the Week 1 artifact is public.
4. Ask two trusted people to mark unclear or unsupported resume claims.
5. Publish the x/365 map and syllabus.

### Days 8 through 14

1. Complete three beginner algorithm sessions.
2. Practice the Week 1 program explanation aloud.
3. Find five alumni or engineers whose work relates to software, finance, or crypto.
4. Read their work before sending a message.
5. Send three narrow questions. Do not ask for a referral in the first message.

## Use the weekly career schedule

### Weeks 1 through 10

- review five suitable roles;
- submit up to five honest applications;
- complete three beginner algorithm sessions;
- send three researched messages;
- attend or schedule one conversation each month;
- improve the resume when the work provides new evidence.

At this stage, general programming ability matters more than crypto vocabulary.

### Weeks 11 through 24

- continue the application and algorithm schedule;
- add the Asset Record Lab after Week 16;
- add the Onchain Ownership Lab after Week 24;
- make one small open-source interaction each week, such as reproducing an issue, improving a test, or correcting documentation;
- practice a 90-second project explanation every Sunday.

### Weeks 25 through 43

- target more crypto, fintech, custody, and digital-assets teams;
- publish the finance and security labs;
- ask engineers to review narrow parts of TreasuryFlow;
- complete one mock coding interview every two weeks;
- request referrals only when the role fits and the relationship has context.

### Weeks 44 through 52

- target Summer 2028 and suitable off-cycle roles;
- complete one coding and one project or system-design mock interview each week;
- send the capstone release candidate to three reviewers;
- tailor the top third of the resume to each high-priority role;
- diagnose the application funnel every 20 qualified applications.

## Diagnose the application funnel

Use evidence before changing tactics:

- No recruiter screens after 20 qualified applications usually points to eligibility, resume, timing, or targeting.
- Recruiter screens but no technical rounds usually points to positioning, communication, or role fit.
- Repeated technical-screen failures point to coding, debugging, or explanation gaps.
- Final rounds without offers require closer review of project depth, behavioral answers, and team fit.

Change one part of the process at a time. Record the result in the private tracker.

## Write project resume bullets

Use this structure:

```text
Action + system and user + difficult technical choice + evidence or result
```

Do not write this:

> Built an ERC-20 token using Solidity.

After TreasuryFlow exists, a supported bullet might look like this:

> Built a permissioned EVM fund prototype with expiring eligibility attestations, role-separated recovery, and indexed reconciliation. Tested supply and authorization properties with Foundry fuzz and invariant suites.

Use only features and test evidence that exist in the repository.

## Use these outreach patterns

### Ask about work you studied

> Hi __. I am learning TypeScript and tokenization through a public 365-day course. Your explanation of ___ changed how I modeled ___. I tried it here: [link]. Am I misunderstanding ___? A link or short correction would help.

### Report that you used the advice

> Your point about ___ was right. I changed ___ and added this test: [link]. The remaining problem is ___. Thank you for the correction.

### Ask about a referral later

> I plan to apply for the ___ internship. The role asks for ___, and this project shows my work on ___: [link]. Based on what you know of the team and my work, do you think I fit? If so, would you feel comfortable referring me? I understand if not.

## Prepare for interviews

| Area | Evidence | Practice |
| --- | --- | --- |
| Programming | weekly TypeScript work | explain code, errors, tests, and complexity aloud |
| Data structures | solved-problem log | three sessions each week, then timed sessions after Week 12 |
| Full-stack systems | Asset Record Lab and TreasuryFlow | APIs, SQL, state, validation, failures, and accessibility |
| Backend reliability | Settlement Failure Lab and capstone | retries, idempotency, queues, transactions, and reconciliation |
| Ethereum and Solidity | Onchain Ownership Lab | transactions, ABI, storage, events, gas, permissions, and reverts |
| Security | Vault Attack Lab and threat models | attacks, assumptions, fuzz tests, invariants, and recovery |
| Tokenization | glossary and both flagships | rights, records, custody, Net Asset Value, and Settlement |
| Behavioral | weekly retrospectives | eight stories about failure, feedback, ambiguity, ownership, and ethics |

## Keep the application tracker private

Use these columns:

```text
company | role | source URL | date found | deadline | location
graduation fit | work-authorization fit | minimum-requirement fit | skill gaps
contact | relationship context | resume version | application date
stage | next action | next-action date | result | lesson
```

Automate reminders and duplicate detection if useful. Do not automate unsolicited messages or mass applications.

## Build an alternative summer if needed

If Summer 2027 does not produce an internship, use the summer for a research assistantship, a university lab, a hackathon, a serious open-source contribution, a scoped project for a small company, or the independently reviewed capstone.

Describe self-directed work accurately. Do not present it as employment.
